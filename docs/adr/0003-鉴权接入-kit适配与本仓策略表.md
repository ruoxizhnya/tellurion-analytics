# 0003 · 鉴权接入：kit net/http 适配 + 本仓策略表

- **状态**：已裁决（来源：裁-15，2026-10-25）
- **场景**：本仓此前只有「鉴权现状登记」（`AuthStatus = "unwired"`），`Server` 不读 `Authorization`、不产出 401/403；安全边界仅靠回环监听。kit `v0.1.1` 已提供 `auth/httpadapter`（`Authenticate` / `Authorize` / `DecideStartup` / `Policy`），机制不需要各服务各写一份。
- **决策**：
  1. **机制在 kit、策略在本仓**：`internal/httpapi/auth.go` 实现 `Authorizer`，内部调 `httpadapter.Authenticate`（Bearer → `Parse` → 拒 `kind != access` → 校验 subject）与 `httpadapter.Authorize`（Public / AnyAuthenticated / Roles，角色 any-of）；`internal/httpapi/policy.go` 保存本仓唯一的「路由 → 角色」表。
  2. **所有端点过闸，fail-closed**：`New` 从同一份路由表注册并逐个包 `requireAuth`；未装配 `Authorizer` → `503 auth_unavailable`，无凭证 / 坏 token → 401，越权 → 403。
  3. **角色口径**：6 个 POST（metrics / benchmark / attribution / sensitivity / montecarlo / correlation）= `trader`；2 个 GET（reports / export）= `viewer`。
  4. **启动闸**：复用 `httpadapter.DecideStartup`——有 secret 开鉴权；无 secret + 回环 = 开放；无 secret + 非回环 = **拒绝启动**（容器须显式 `AUTH_INSECURE_EXPOSURE=loopback-published`）。
- **理由**：token 校验、refresh/access 区分、角色 any-of 与启动闸是跨服务同一套语义，留在 kit 才不会漂移；「哪个端点要哪个角色」是本仓业务，留在本仓才可审计。策略表与路由表同源注册，守卫测试双向对拍，漏登即红。
- **代价 / 后果**：
  - 新增对 `github.com/ruoxizhnya/tellurion-kit v0.1.1` 的依赖（其编译闭包含 gin，但本仓源码不 import gin）。
  - 鉴权开启后，core / UI 调用本服务必须持有效 access token（POST 需 `trader` 及以上，GET 需 `viewer` 及以上）；token 分发不在本仓。
  - 非回环且未配 secret 的进程直接起不来，这是有意的失败方向；默认 `127.0.0.1:8087` 仍保持本地 open-access。
- **替代关系**：不替代 0001 / 0002；把 `docs/api-schema.md` §7 的「未接线」现状登记翻转为 `enforced`。
