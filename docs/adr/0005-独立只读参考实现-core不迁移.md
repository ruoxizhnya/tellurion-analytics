# 0005 · 定位为独立只读分析服务，core 指标实现不迁移

- **状态**：已裁决（2026-11-10，主任）
- **场景**：ADR-036 §3 的 G3 要求 core/UI 至少一条真实调用，并删除 core 重复指标/报告实现。本仓 8 端点已就位，但 2026-10-26 与 2026-11-10 两轮复核均实测 core 非测试 Go 对 analytics 零命中；同轮 core `SVC-CORE-AN-RETIRE` 收口结论 = **保留并冻结**（`pkg/backtest/metrics` / `reporting` 生产 import 恰 3 条，已进 repoguard 冻结快照），且 K7（`analysis.benchmarks` 生产写者为 0）未解除。G3 的「core 加 HTTP 客户端 + 切读 + 删重复实现」三项前提均不成立。
- **决策**：
  1. 本仓定位为**独立只读分析服务 / 参考实现**：提供基准、归因、敏感性、蒙特卡洛 8 端点，单仓自证可用，不承担 core 迁移目标。
  2. core `pkg/backtest/metrics` / `reporting` **保留并冻结**，不删除、不迁移；本仓不 import core 实现包（ADR-0001）。
  3. `SVC-AN-G3` 从 open 项**撤销/关闭**，不再以「有消费者」为验收目标。
  4. K7（`RegisterBenchmark` 零生产调用）**挂起**：`analysis.benchmarks` 保留表与读路径，生产写者为 0 的事实继续登记；不伪造消费者。
  5. 数据流方向维持「本仓只读上游（core / data / orchestration），只写自己的 `analysis.*`」；不新增 core → 本仓调用。
- **理由**：全量迁移（原 C 案）要改 core 运行时——`engine.go` 每次 run 调 metrics、`cmd/dualrun` 用它做等价判定；且本仓只覆盖 volatility/VaR/CVaR/buildMetricsPayload，Sharpe/Sortino/Calmar/回撤/交易统计等全量面仍在 core，切换会造成回测口径不可逆变化。最小接线（原 B 案）在无产品需求时没有用户价值。两案均劣于「独立服务 + core 冻结对照」。
- **代价 / 后果**：core 双实现长期并存（由冻结护栏防止漂移）；本仓无生产消费者，运维优先度低于其他服务；K7 永久挂起。若未来产品确需统一分析 API，必须新立 ADR + 任务单，不得直接解冻已删/冻结路径。
- **替代关系**：修订 ADR-036 §3 对本仓 G3 的适用范围与 §6 的 analytics 退役行；不影响 ADR-036 对其他仓的结论。
